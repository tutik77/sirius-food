# ЛР № 3. Ответы на контрольные вопросы

**1. Чем аутентификация отличается от авторизации? Пример ошибки на каждом уровне.**
Аутентификация отвечает на вопрос «кто ты?»: проверка пароля при входе и подписи JWT при каждом запросе
(`get_current_user`). Авторизация отвечает на вопрос «что тебе можно?»: роль (`require_role`) и права
на конкретный объект (проверки в сервисах). Ошибка аутентификации: сервер не проверяет подпись токена
или срок действия, и злоумышленник выдаёт себя за другого пользователя. Ошибка авторизации: пользователь
вошёл честно, но сервер не проверил, что заказ его, и студент отменяет чужой заказ (IDOR).

**2. Почему `user_id` убирают из payload запроса и берут из JWT?**
Тело запроса целиком под контролем клиента: подставить чужой `user_id` может кто угодно.
JWT подписан секретным ключом сервера, и изменить `sub` без ключа нельзя: подпись перестанет сходиться.
Поэтому `OrderCreate` больше не содержит `user_id`, а заказ создаётся на `current_user.id`.
Если клиент всё же пришлёт `user_id`, поле будет проигнорировано (тест `test_order_is_created_for_token_owner_not_payload_user`).

**3. Что такое IDOR и на каком слое от него защищаются?**
Insecure Direct Object Reference: сервер принимает идентификатор объекта от клиента
(`/orders/{order_id}/cancel`) и не проверяет, имеет ли текущий пользователь право на этот объект.
Защита в Service-слое (`order.belongs_to(current_user)` в `OrderService.cancel_order`): это бизнес-правило
«отменить можно только свой заказ». Тогда правило работает при любом способе вызова (HTTP, CLI, воркер),
тестируется без HTTP и не размазывается по роутерам. К тому же только сервис загружает объект
и знает его владельца.

**4. Почему payload JWT нельзя считать защищённым?**
Payload только кодируется в Base64URL, но не шифруется: любой может его декодировать и прочитать.
Подпись гарантирует целостность (содержимое не подменили), но не конфиденциальность. Поэтому в токене
только `sub`, `type`, `iat`, `exp`, `jti`: ни паролей, ни email, ни персональных данных.

**5. Почему роль проверяется в API-слое, а права на объект — в Service-слое?**
Для проверки роли достаточно данных из токена и названия эндпоинта: это правило доступа к точке входа
(«кухня — только для повара»), и `require_role` отсекает запрос до бизнес-логики. Права на объект
зависят от данных самого объекта (кто владелец заказа, какой курьер назначен). Их можно проверить,
только загрузив объект, а это делает сервис через репозиторий. Кроме того, это бизнес-правило,
и оно должно соблюдаться при любом входе в систему.

**6. Зачем rate limiting на Redis, а не в памяти приложения?**
В продакшене приложение запускается в нескольких репликах (процессах, контейнерах). Счётчик в памяти
у каждой свой: при 4 репликах злоумышленник получает 4×5 попыток в минуту, а после перезапуска счётчик
обнуляется. Redis — общее хранилище для всех реплик, атомарный `INCR` и TTL ключа (`EXPIRE`) дают
корректный счётчик в окне.

**7. Что такое Secure by Default? Три примера из проекта.**
Безопасное поведение по умолчанию: чтобы ослабить защиту, нужно явно это настроить, а не наоборот.
В проекте: (1) `SECRET_KEY` и `DATABASE_URL` обязательны, без них приложение не запускается, слабый
ключ короче 32 символов отклоняется; (2) `DEBUG=False` по умолчанию, поэтому Swagger и `openapi.json`
выключены; (3) CORS по умолчанию не разрешает ни одного домена, только перечисленные в `ALLOWED_ORIGINS`.
Ещё: регистрация всегда даёт роль `student`, пользователи после миграции получают непригодный для входа
хеш `!`.

**8. Почему «`service.py` импортирует `HTTPException` для ошибки 403» нарушает правило зависимостей?**
`HTTPException` принадлежит FastAPI, то есть внешнему кругу Frameworks & Drivers. Внутренний круг
(бизнес-логика) не должен знать о внешних: иначе сервис не переиспользовать в CLI (`app/cli.py`)
или фоновой задаче, а смена фреймворка затронет бизнес-правила. В проекте сервис бросает доменное
исключение `AccessDeniedError(ForbiddenError)`, а роутер переводит его в 403 через `to_http()`.
Отсутствие импортов `fastapi` в `service.py` проверяет `tests/test_architecture.py`.
