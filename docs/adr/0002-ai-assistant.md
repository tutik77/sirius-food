# ADR 0002. AI-ассистент: модель, векторная БД, агент

Статус: принято. Трек F учебной практики.

## Контекст

Клиенты спрашивают «что есть вегетарианское», «сколько стоит доставка», «где мой заказ», «сколько у меня баллов».
Ответ должен опираться на данные «Сириус.Еды» (меню, правила, заказы клиента), а не на фантазию модели; при
недоступности модели сервис не должен падать; ассистент не должен раскрывать чужие данные.

## Решения

**1. Модель — `google/gemini-3.8-flash` через OpenRouter.**
Быстрая и дешёвая модель с поддержкой вызова инструментов и хорошим русским. OpenRouter даёт OpenAI-совместимый API:
`ChatOpenAI` из `langchain-openai` с `base_url` OpenRouter, модель меняется одной переменной `ASSISTANT_MODEL`
без правок кода. Локальная Ollama отклонена: нагрузка на ноутбук и слабее tool calling у малых моделей.

**2. Эмбеддинги — `openai/text-embedding-ada-002` через тот же OpenRouter.**
Один ключ и один клиент (`OpenAIEmbeddings`) на всё; многоязычные векторы 1536 измерений, для десятков документов
меню и FAQ стоимость пренебрежимо мала. Новые модели (`text-embedding-3-small`) дешевле — замена одной настройкой
`EMBEDDING_MODEL` плюс переиндексация.

**3. Векторная БД — Qdrant, а не pgvector.**
Отдельный сервис в docker-compose, готовая интеграция `langchain-qdrant`, фильтрация по метаданным (`source`),
UI на :6333/dashboard. pgvector сэкономил бы контейнер (тот же PostgreSQL), но потребовал бы расширения в образе БД
и миграции; для учебного стенда Qdrant проще и ближе к промышленным RAG-системам.
Цена — ещё один сервис и индекс, который надо пересобирать при изменении меню (`python -m scripts.index_knowledge`).

**4. Агент на LangGraph с инструментами, а не одна цепочка «поиск → ответ».**
`create_agent` (ReAct-граф LangGraph) сам решает, какие инструменты вызвать:
`search_knowledge` (RAG по Qdrant: эмбеддинг вопроса → векторный поиск → документы в контекст модели),
`my_orders` (история и статусы заказов), `my_loyalty` (баллы, уровень, действующие промокоды — связь с треком A).
Один вопрос «повторить прошлый заказ со скидкой?» требует и заказов, и промокодов — цепочке пришлось бы всегда
подмешивать всё в промпт.

**5. Безопасность контекста.**
Инструменты создаются на каждый запрос и замкнуты на текущего пользователя из JWT (`build_tools(user, …)`);
у них нет параметра `user_id`, поэтому модель, даже под prompt injection, не может запросить чужие заказы.

**6. Надёжность и наблюдаемость.**
`AssistantService` не знает о LangChain: работает через интерфейс `AssistantAgent`. Любая ошибка модели, Qdrant
или сети → ответ «Извините, ассистент сейчас недоступен. Попробуйте позже.», флаг `is_fallback`, лог с
traceback. Таймаут модели 30 с, один ретрай. Метрики Prometheus: `assistant_response_seconds` (гистограмма времени
ответа), `assistant_requests_total{outcome}`, `assistant_feedback_total{helpful}`. Каждый вопрос и ответ
сохраняются в `assistant_messages` с временем ответа и оценкой пользователя (релевантность).

## Последствия

- Ответы опираются на факты, но качество зависит от индекса: после изменения меню нужна переиндексация.
- Ответ занимает секунды (2–3 вызова модели при использовании инструментов) — для чата приемлемо.
- Внешняя зависимость (OpenRouter): при её недоступности остальной сервис работает, ассистент отвечает fallback.
